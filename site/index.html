01 / MODELOS

Elige quién hace cada parte.

Un catálogo propio. Modelos distintos para planificar, ejecutar, verificar, documentar y compactar. Defaults globales, por proyecto y para el próximo mensaje.

  • Configura endpoints, visión, contexto y tarifas.
  • Consulta el modelo efectivo de cada rol.
  • El grafo tiene su propio planificador y alternativas.

Las capacidades y tarifas son configuradas. Probar un modelo en Relay hace una llamada real al proveedor.

02 / CONTEXTO

El código tiene relaciones. El proyecto, memoria.

CBM construye un grafo consultable del repositorio. El agente puede buscar símbolos, seguir llamadas, analizar impacto y leer el código que necesita.

  • Indexación individual, por lote y watcher de cambios.
  • Resúmenes FTS5 y hechos aprobados del proyecto.
  • Archivos, skills y SQL se consultan bajo demanda.
  • Genera diagramas desde el grafo y guarda Mermaid o SVG explícitamente.

Cada fuente tiene su alcance. La memoria se recupera por solicitud y los hechos requieren su opción de proyecto; CBM es un componente externo.

Leer funcionamiento y límites ↗

03 / EJECUCIÓN

El plan puede cambiar al encontrar más trabajo.

Las tareas tienen dependencias y resultados. Las que están listas pueden avanzar en paralelo cuando no hay conflictos. Si una tarea necesita dividirse, el grafo conserva el avance y reorganiza las dependencias.

  • Planificación, ejecución, verificación y registro.
  • Subdivisión acotada desde el resultado parcial.
  • Intervención humana y límites explícitos de ejecución.

La subdivisión de esta edición es de un nivel. Un turno terminado no significa por sí solo que el pedido esté cumplido.

Leer funcionamiento y límites ↗

04 / WORKSPACE

Conversar, revisar y continuar. A la vista.

Mantén varias conversaciones y herramientas abiertas. Separa una respuesta, una tabla o un SVG del hilo y vuelve a su origen cuando lo necesites.

  • Ventanas independientes, mosaico y acceso por teclado.
  • Rama, worktree y diff asociados a la tarea.
  • La misma PR puede recibir correcciones de revisión y CI.

El seguimiento de PR se activa con límites. Los worktrees separan archivos; comparten recursos de la máquina.

Leer funcionamiento y límites ↗

05 / EQUIPO

Cada persona sabe dónde puede trabajar.

Admin, Subadmin, Dev y Finanzas tienen alcances distintos. El Admin asigna proyectos y cada persona conecta sus propias cuentas.

  • Permisos por proyecto comprobados por el backend.
  • GitHub conserva la identidad de quien realiza la acción.
  • Asignar, habilitar escritura y continuar son pasos distintos.

Publicar una PR requiere su permiso; merge y despliegue son decisiones posteriores. No hay asignación individual por nodo del grafo.

Leer funcionamiento y límites ↗

06 / CLIENTE → PROYECTO

Lo que se ejecuta pertenece a un proyecto. Y a un cliente.

Consulta el seguimiento comercial y vincula clientes u oportunidades con proyectos. Desde ahí, llega al repositorio, al tablero de GitHub y al trabajo asociado.

  • Instantánea de empresas, oportunidades y contactos del CRM.
  • Vínculos explícitos con proyectos y acceso a issues y PR.
  • Contexto para priorizar y seguir la entrega.

El CRM externo conserva los registros de negocio. Convertir una oportunidad en trabajo sigue siendo una decisión del equipo.

Leer funcionamiento y límites ↗

07 / ACTIVIDAD

Mira el avance. Entiende el consumo.

Ejecutar también implica observar. Estado, En curso, informes, métricas y logs ayudan a revisar qué ocurrió y dónde se utilizó el contexto.

  • Actividad y resultados por proyecto y modelo.
  • Entrada, salida y caché cuando el proveedor la reporta.
  • Night Runs inicia trabajos configurados con comprobaciones.

Los costos son estimaciones con tarifas configuradas, no facturas. Night Runs no incluye un scheduler horario automático.

    HECHO DESDE EL TRABAJO REAL

    Nació de trabajar con clientes. Crece con el equipo y los modelos.

    Relay fue creciendo en FourBis para mantener contexto entre repositorios, delegar ejecución y seguir proyectos de clientes. La configuración de modelos, la memoria, los permisos y la continuidad responden a esas necesidades.

    Cuando aparece una nueva capacidad de IA, puedes incorporarla sin perder la referencia del proyecto, las personas y el proceso de GitHub. Cada integración se configura y se comprueba en el entorno donde se utiliza.

    CÓMO FUNCIONA

    La continuidad tiene dónde vivir.

    01 / WORKSPACE

    Conversaciones y herramientas

    Ventanas, archivos, tablas, diagramas y diff. Una API local conecta la interfaz con el trabajo del proyecto.

    02 / CONTEXTO

    Repositorio y memoria

    CBM para el grafo de código; SQLite para estado, historial y resúmenes; skills y archivos bajo demanda.

    03 / RUNNER

    Modelos y herramientas

    Etapas configurables que usan archivos, shell, SQL, Git y MCP según permisos y alcance del proyecto.

    04 / EVIDENCIA

    Resultados que se revisan

    Cambios, comprobaciones, veredictos y consumo. Publicar una PR deja el trabajo disponible para revisión.

    MÁS HERRAMIENTAS, EL MISMO PROYECTO

    Incorpora tu forma de trabajar.

    Habilita las capacidades que necesita el proyecto. Cada integración requiere su configuración y permisos.

    Servidores MCP y skills

    Registra herramientas y procedimientos, define su alcance por proyecto y carga las instrucciones pertinentes bajo demanda. Comprueba la conexión antes de usar un servidor.

    SQL, shell y comandos

    Consulta conexiones registradas, compila, prueba o ejecuta acciones por nombre, con argumentos y registro de ejecución. El entorno y los permisos de la tarea determinan lo disponible.

    Gmail y Google Calendar

    Conecta Gmail personal para consultar correo y preparar borradores con confirmación de envío. Las herramientas de Calendar tienen una configuración de proceso separada y un modo real explícito.

    Voz, Discord y VS Code

    Transcribe audio y procésalo con un experto, o conecta puntos de entrada y notificaciones complementarios. Requieren un endpoint de transcripción, bot, extensión o receptor.

    Explóralo. Léelo. Ejecútalo localmente.

    Software experimental con licencia MIT. Validado en Windows con Python 3.11+ y PowerShell. El uso de proveedores de modelos puede tener su propio costo.

cd 4bis.relay-showcase
python -m venv .\mcp-server\.venv
